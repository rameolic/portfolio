Engineering Case Study

Real-Time School Bus Tracking

Contributed to architecture and implementation of live tracking for approximately 100 GPS-equipped school buses within the InsightsE ecosystem.

Context Technical approach Lifecycle & listeners Outcomes

Context

Parents and school stakeholders need timely visibility into school transport. The system supports approximately 100 GPS-equipped buses. The mobile experience must show map positions that stay current without becoming fragile when the app backgrounds, reconnects, or receives delayed GPS updates.

Technical approach

  • REST APIs retrieve initial location data when the tracking experience starts.
  • Cloud Firestore snapshot listeners deliver real-time location updates after bootstrap.
  • Google Maps visualizes bus positions for end users.
  • Stale-location detection helps identify when a reported position should no longer be treated as fresh.
  • Application lifecycle handling keeps subscriptions aligned with foreground/background behavior.
  • Listener cleanup and reconnection handling reduce leaks and missed updates after interruptions.

Important: school bus tracking does not use WebSockets for live location. Real-time updates are driven by Firestore snapshot listeners after the initial REST fetch.

Why listener and lifecycle management matter

Real-time listeners are easy to attach and easy to get wrong. If subscriptions outlive the screen or app state that needs them, clients waste resources and can show outdated markers. If they are torn down too aggressively—or never re-established after reconnect—users see gaps in tracking.

Production work therefore treated listener scope, cleanup, stale detection, and reconnection as part of the feature—not optional polish.

Outcomes

  • Live map tracking for roughly 100 GPS-equipped buses
  • Clear separation between initial REST load and continuous Firestore updates
  • Operational attention to stale data and mobile lifecycle edge cases
