Engineering Case Study

Real-Time School Bus Tracking

Live transport visibility for approximately 100 GPS-equipped school buses within the InsightsE ecosystem.

Introduction Context My role Approach Architecture Challenges Outcomes

Project introduction

Parents and school stakeholders need timely bus location on a map. I contributed to the architecture and implementation of a real-time tracking experience designed for roughly one hundred GPS-equipped buses.

Problem / business context

GPS feeds arrive continuously, mobile apps background and resume, and locations can become stale. The product needed a first paint of known positions, then continuous updates, without leaking listeners or showing outdated markers after lifecycle events.

My role and responsibilities

  • Architecture contribution for live tracking
  • REST bootstrap for initial locations
  • Cloud Firestore snapshot listener integration
  • Google Maps visualization
  • Stale-location handling
  • Listener lifecycle, cleanup, and reconnection behavior

Technical approach

The client loads an initial set of locations through REST APIs, then attaches Cloud Firestore snapshot listeners for live updates. Google Maps renders markers. Stale-location rules and application lifecycle hooks keep subscriptions aligned with what the user is actually viewing.

Data flow diagram

Engineering challenges and solutions

Real-time subscriptions are easy to attach and easy to leave running too long. Listener scope, cleanup on dispose/background, and reconnection after network gaps were treated as part of the feature. Freshness rules help the UI distinguish a live update from a stale last-known position.

Verified outcomes

  • Tracking support for approximately 100 GPS-equipped buses
  • Clear split between REST initial load and Firestore live updates
  • Map visualization with operational attention to lifecycle and stale data
