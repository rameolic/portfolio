Engineering Case Study

InsightsE Canteen — Flutter Desktop POS

A production desktop point-of-sale for school canteen operations, integrated with the InsightsE education ecosystem.

Introduction Context My role Approach Architecture Offline lifecycle Challenges Outcomes

Project introduction

InsightsE Canteen is a Flutter desktop POS used for wallet-based canteen transactions. I independently designed, developed, and delivered the production application in one month—covering architecture, UI, hardware integrations, offline behavior, and release readiness.

  • Flutter Desktop
  • Dart
  • BLoC
  • NFC/RFID
  • Thermal Printing
  • ERPNext APIs

Problem / business context

Canteen counters need fast identification and payment flows, printed receipts, and resilience when network connectivity is unreliable. The client had to fit into an existing education-management backend landscape while remaining usable during intermittent connectivity.

My role and responsibilities

  • Application architecture and Flutter desktop UI
  • BLoC-based state management
  • NFC/RFID scanner integration
  • Thermal printer integration for receipts
  • Wallet transaction workflows
  • Offline transaction management and synchronization
  • ERPNext API integration on the client
  • Testing and production delivery within one month

Technical approach

The desktop client owns the counter experience: identify a user via NFC/RFID, complete a wallet transaction, print a receipt, and synchronize with ERPNext-backed APIs. Offline-capable handling keeps the counter productive when the network drops, then reconciles when connectivity returns.

System integration diagram

Offline transaction lifecycle

  1. A transaction is initiated at the POS.
  2. The application processes it through an offline-capable workflow.
  3. When connectivity is unavailable, transaction data is queued.
  4. Pending items synchronize when connectivity returns.
  5. Backend acknowledgments confirm successful sync.
  6. Unique transaction identifiers support duplicate prevention.

Engineering challenges and solutions

Hardware timing, receipt formatting, and intermittent networks all collide at the counter. The approach kept identification, printing, and sync as explicit stages in the client workflow so each concern could fail and recover without blocking the entire sale path. ERPNext integration stayed on the client/API boundary—I did not build the ERPNext backend.

Verified outcomes

Independently delivered a production Flutter desktop POS with NFC/RFID scanning, thermal printing, and offline transaction synchronization in one month.
