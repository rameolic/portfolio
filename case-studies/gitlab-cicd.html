Engineering Case Study

GitLab CI/CD for Android & iOS

Personal ownership of mobile build pipelines built from scratch—automating compilation and artifact generation while keeping store publication manual.

Scope Pipeline Release practices

What I built

  • Tag-triggered builds for intentional release candidates
  • Dependency installation and Flutter/platform setup in CI
  • Android APK/AAB generation
  • iOS IPA generation
  • Signing and provisioning workflows
  • Build artifact generation for downstream release steps

Google Play Store and Apple App Store publication were managed manually. This case study does not claim fully automated store publishing.

Branching and release troubleshooting

Pipelines sit alongside Git branching practices used for feature work and release preparation. When builds fail—dependency drift, signing mismatches, or platform tooling issues—I troubleshoot through the CI logs and local reproduction to restore a reliable release path.

The value of the pipeline is repeatability: the same tagged revision produces the mobile artifacts used for store submission, reducing “works on my machine” variance during release week.
